# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

`spatInfer` is an R package implementing Conley and Kelly (2024): spatial basis regressions with large-cluster inference, plus spatial-noise placebo and synthetic-outcome diagnostics. It supports three estimators: BCH (Bester-Conley-Hansen), IM (Ibragimov-Mueller) and SCPC (Mueller-Watson).

The user workflow is `optimal_basis()` → `placebo()` → `synth()` (or both at once with `placebo_synth()`, which has a cli progress bar, shown by `placebo_synth_table()`) → `bch_regression()` / `im_regression()` / `scpc_regression()`, with `placebo_table()`, `synth_table()` (every inference method in one table), `combined_table()` (the HC row and the chosen BCH/IM/SCPC rows, `select=c(BCH=7, IM=5, SCPC=0.04)`, with their synth p values; `iv_combined_table()` for IV, with `ar_select` for the AR block), `im_table()` and `regression_table()` for output. Instrumental variable regressions use `iv_placebo()` and `iv_synth()` (or `iv_placebo_synth()`), which report 2SLS and Anderson-Rubin tests, then `iv_bch_regression()`.

## Commands

Run from the package root:

```r
devtools::document()                 # regenerate man/ and NAMESPACE (roxygen; never edit those by hand)
devtools::test()                     # full test suite
devtools::test(filter = "scpc")      # one file: tests/testthat/test-scpc.R
testthat::test_file("tests/testthat/test-golden.R")
devtools::check()
devtools::build_readme()             # README.md is generated from README.Rmd; edit the .Rmd
```

To regenerate golden fixtures, run `Rscript tests/testthat/fixtures/make-golden.R [case ...]`. Do this only when a change in results is intended and explained. Case names are the keys of `golden_cases` in `helper-golden.R`, which match the `.rds` basenames. `scpcR_reference.rds` is not one of them. It was recorded from scpcR itself, which is no longer a dependency, so it can't be regenerated and must never be overwritten.

## Architecture

**Placebo vs synth.** Both kinds of test have the same pipeline, implemented in `R/spatial_helpers.R`:
1. `prepare_spatial_data()` validates input (coordinates must be named `X`/`Y`). Every function's `weights` argument names the weighting column as a string, or is `NULL`. `regression_weights()` checks it and copies it to `wts`, which all fits use. `prepare_spatial_data()` then renames the outcome to `dep_var` and the first RHS variable (the treatment) to `explan_var`, then appends the principal components of an `mgcv` tensor-spline basis (`prin_comp()`).
2. `build_formulas()` builds `eq_est` and `eq_sim`. In `eq_sim`, simulated noise `sim` replaces the treatment (placebo, `sim_replaces="explan_var"`) or the outcome (synth, `"dep_var"`).
3. `Noise_Sim()` fits a Matérn model to the residuals by an MLE range search with `fields::Krig`. It then draws `nSim` noise columns using an exact Cholesky decomposition, or `BRISC` when `exact_cholesky=FALSE`. The placebo takes residuals from regressing the treatment on the PCs. The synth takes residuals from regressing the outcome on a quadratic in X/Y.
4. `ols_sim()` fits each simulated regression once and gives its HC p value, BCH and IM p values for each set of clusters, and SCPC p values for each `avc` (only when `avc` is given). `ols_summary()` does the same for the real data and builds the `Results` data frame: an HC row, BCH rows, IM rows, then SCPC rows, whose `Clusters` holds `avc`. The IM helpers (`im_cluster_coefs()`, `im_t_test()`) are in `im_helpers.R` and the SCPC ones (`scpc_setup()`, `scpc_stats()`) in `scpc_helpers.R`.

Each user function is a thin wrapper: `sim_inputs()` (`iv_sim_inputs()` for IV) does step 1 and builds the clusters and SCPC spatial weights, then `placebo_run()`, `synth_run()`, `iv_placebo_run()` or `iv_synth_run()` does the rest. `placebo_synth()`/`iv_placebo_synth()` (`R/placebo_synth.R`) share one set of inputs between the two `_run()` calls and pass them a progress bar from `sim_progress()`. `run_sims(progress=)` then runs the simulations in about 20 batches and reports after each. On PSOCK workers the simulation function is sent once (`assign_sim_fun()`/`call_sim_fun()`), not once per batch. Results must be identical to the separate functions, and `test-placebo-synth.R` checks this against the golden files.

Clusters come from `sim_clusters()`: k-medoids clusters (`cluster::pam`, or `clara` when `k_medoids=FALSE`) for 3..`max_clus` clusters; there is no 2-cluster row.

**IV** (`R/iv_helpers.R`, `iv_placebo.R`, `iv_synth.R`) handles one endogenous treatment and one instrument, with fixest formulas `y ~ controls | x ~ z`, renamed to `dep_var`, `explan_var` and `inst_var`. Each simulated draw (`iv_sim()`) tests 2SLS (`fit_*` term) and Anderson-Rubin, each with HC, BCH, IM and SCPC (one per `avc`, only when `avc` is given), for every cluster count. SCPC on 2SLS goes through `scpc_coef_stats()`, which for IV fits uses fixest's `iv.rhs2` design (instrumented treatment) with structural residuals, i.e. 2SLS treated as least squares on X-hat. IV uses clusters 3..`max_clus`; there is no 2-cluster row. AR follows Chernozhukov and Hansen (2008), "The reduced form", implemented in `R/iv_ar.R`, whose header holds the derivation for each inference. `b` is rejected when the instrument is significant in the regression of `y - b*x` on the instrument and exogenous regressors. OLS is linear in the dependent variable, so `ar_reduced_forms()` fits the reduced forms of y and x once. Each of `ar_hc()`, `ar_bch()`, `ar_im()` (reduced forms within each cluster) and `ar_scpc()` returns the coefficients, a 2x2 variance `V` and a squared critical value `crit` that does not depend on b. `ar_conf_set()` then solves the quadratic exactly; the set may be two rays or the whole line. At b = 0 the test is the reduced form test of the outcome, which gives the AR "Est p" and simulated p values. HC/BCH variances replicate fixest's small-sample corrections, and `test-iv.R` checks them against fixest. The SCPC critical value is conditional on the regressors only (`scpc_cond_Oms()`, shared with `scpc_coef_stats()`). Every HC and BCH Results row has a first-stage F with its own inference and cluster count, so there is no single F: the squared first-stage t (`ar_F()`). IM and SCPC rows, and `iv_im_regression()`/`iv_scpc_regression()`, deliberately have no F (`NA`, shown blank in tables). AR HC and BCH rows share the F of their inference. In AR SCPC rows `Clusters` holds `avc`. `placebo_table()`/`synth_table()` share `sim_table()` (in `R/placebo_table.R`), which for IV results shows a 2SLS block then an AR block (`table_rows()`, `tinytable::group_tt()`). `iv_combined_table()` (`R/iv_combined_table.R`) is the IV counterpart of `combined_table()`, which rejects IV results; both pick rows with `pick_row()`. In `iv_placebo()` the placebo instrument is `a + b*x_sim + e_sim`. Here `e_sim` comes from a second `Noise_Sim()` call with its own seeds (`seeds=c(5678,567), trend=FALSE`). Keep those seeds distinct from the treatment draw. `iv_bch_regression()` (BCH/HC), `iv_im_regression()` (IM; class `c("iv_im_regression","iv_regression")`) and `iv_scpc_regression()` (SCPC, one `avc`; class `c("iv_scpc_regression","iv_regression")`) share `iv_basis_regression()`, each with AR under its own inference. They must agree exactly with the matching `iv_placebo()` rows, and `test-iv.R` checks this. IV results go to `iv_regression_table()`/`iv_regression_plot()` (`R/iv_regression_table.R`). The generic `regression_table()` rejects them with an error pointing to those functions. It fits on the renamed data from `prepare_iv_data()`, then refits with the original treatment and instrument names so its terms read `fit_<treatment>`. The original standalone prototypes are in `../IV/`.

**SCPC** (`R/scpc_core.R`) is ported from scpcR 0.1.3 (MIT; its licence is kept in the file header). It must reproduce scpcR's results: `test-scpc.R` compares against `fixtures/golden/scpcR_reference.rds`. scpcR is no longer a dependency. Weighted regressions follow scpcR by default: conditional SCPC leaves the regressors unweighted. The user option `scpc_weighting="sqrt"` rescales them by √w instead (`scpc_cond_weights()`). The choice is stored as `cond_weights` in each spatial-weights object from `scpc_spatial()`/`scpc_setup()`, and `scpc_cond_Oms()` reads it there, so it needs no extra argument downstream. The golden cases `placebo_weighted`/`synth_weighted` were recorded under √w and now pass `scpc_weighting="sqrt"`. The `*_weighted_scpcr` cases and `iv_placebo_weighted_scpc` cover the default. The large-sample approximation's distances in degrees (`scpc_ln_W()`) are a known scpcR bug, documented but deliberately kept.

**Parallelism.** Every simulation loop goes through `run_sims()`. It uses forked `mclapply` on Linux only. macOS and Windows use a PSOCK cluster, because Accelerate BLAS is not fork-safe. Workers are pinned to one BLAS thread (`RhpcBLASctl`) and optionally one fixest thread, and the user's settings are restored on exit. Noise is generated serially before any parallel step, so parallel results must be *identical* to serial ones.

**Side-effect contract.** Simulation functions call `withr::local_preserve_seed()`, which leaves the user's RNG state untouched, and set fixed seeds internally. Plotting restores `par()`. `test-side-effects.R` enforces this.

## Tests

- `test-golden.R` holds characterization tests. Outputs must match the `.rds` files in `tests/testthat/fixtures/golden/` to a relative tolerance of 1e-10. The shared fixture is a deterministic 99-row subset of `opportunity` with small settings, defined in `helper-golden.R` (`run_sim()`, `run_scpc()`). Any numerical change in a method will break these tests. Treat that as a regression unless the change is intended.
- `optimal_basis` golden checks use a 1% tolerance for nearly saturated rows (5×5 tensor, ≥23 PCs), because those rows are BLAS-dependent.
- A golden test is skipped, not failed, when its `.rds` is missing (`expect_matches_golden()`). A case newly added to `golden_cases` tests nothing until you run `make-golden.R <case>`.
- The `placebo_brisc` golden case is skipped when BRISC (Suggests only) is not installed, so a passing suite may not have exercised `exact_cholesky=FALSE`.
- `test-parallel.R` mocks `use_fork()` to test both back ends. It is skipped on CRAN and with fewer than 4 cores. PSOCK workers (used on macOS) load the *installed* spatInfer, not the `load_all()` copy. Tests of new internal functions therefore fail with "could not find function" until the package is installed. Install into a temporary library and put it first in `R_LIBS` to avoid replacing the user's copy.
- The IV fixture (`iv_fixture_data()`, every 6th row of `autor_china` for 2000–07) has a weak instrument (F ≈ 2). Its golden files include unbounded AR sets.

## Code style

The package uses `=` for assignment, base-R pipes `|>`, and `pkg::fun()` calls (only `stats` is imported wholesale). Internal comments use `######` banners. Simulation functions return plain lists such as `Results`, `Spatial_Params` and `Estimates`, without S3 classes. Record user-visible changes in `NEWS.md`. Datasets (`opportunity`, `autor_china`) live in `data/*.rda` and are documented by roxygen in `R/opportunity.R` and `R/autor_china.R`; keep the two in step.
